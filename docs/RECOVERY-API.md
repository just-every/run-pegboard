# Native recovery

Archive and trash retain the original graph. Review through `/api/v1/recovery/preview`, then submit the returned token to `/api/v1/recovery/apply`. Supported types are `project`, `task`, `proof_version` and `attachment`. Proof-backed files use their proof version door. Restoration rechecks current authority and refuses a changed review. Erasure is separate and irreversible.

A task with dangling dependencies remains held. Preview with `repair: "detach_missing_dependencies"` to review detaching only links whose task endpoint is physically absent. The reviewed restore applies that repair atomically. Retained or hidden dependencies are never detached by this option. Missing parent, team, section and project placement still require recovery work.

Workflow bundles author fixed new-task rules through the existing Settings door. A reviewed rule can set priority, a fixed assignee and literal start and due dates. Its `actions` array accepts one of each `kind`: `complete`, `comment`, `collaborator`, `project`, `subtask` and `tag`. Every kind except `complete` takes a `value`: the comment or subtask title, or the selected person's, project's or tag's identity. The activation preview names those selections. A collaborator must already be able to read the task; an additional project requires the activating administrator's current rule authority. Approval tasks cannot be completed automatically. Dates that reach a dependency cascade are refused before any effect applies.

Processing a queued rule commits its work and owned effects in one transaction. The run retains its definition version, activation epoch and activating administrator. Generated subtasks do not recursively trigger the same new-task rules. Disabled, changed or unauthorized activation produces a visible cancellation cause. Repeated processing cannot repeat an applied run.

Read `/api/v1/recovery/rules/:id/undo-preview` using the run identity, then submit its token to `/api/v1/recovery/rules/:id/undo`. The bulk recovery screen exposes the same review with each effect identity. Current edit authority must cover every affected task home. Later field writes, reintroduced relationships, newer human decisions and later work on generated subtasks remain explicit conflicts. Mutation counters survive editable activity expiry. Unchanged generated subtasks enter retained trash. Undo does not restore a previous approval or recall an outside message.

Shared field history is available at `/api/v1/fields/:id/revisions`. Preview a `fromVersion` through its `/preview` suffix and confirm through its `/restore` suffix. Every attached project requires current field-management authority. Restoration appends a new definition and preserves current task values; an incompatible value prevents restoration. Existing installations begin with their current retained definition; earlier snapshots are not invented.

For one retained template or workflow component, preview `fromVersion` and `component` at `/api/v1/workflow-bundles/:id/revisions/preview`, then confirm the returned token at `/api/v1/workflow-bundles/:id/revisions/restore`. Only the selected component is merged into a new immutable revision. Other newer components, adopted project configuration, existing tasks and human decisions remain in place. Adopting that revision into projects is a separate reviewed action.

Full PEG-012 triggers and PEG-094 computed dates, configuration trash beyond these stores, broader graph repair, reviewed trash expiry and undo of schedule cascades and delivery-register changes remain open.
