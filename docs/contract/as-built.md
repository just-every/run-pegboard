# As built

How the done and partial clauses of CONTRACT.md are built today, moved out of the clause text in the 28 October 2026 contract cleanup. This is mechanism, not acceptance: CONTRACT.md holds the only acceptance text and status.

## PEG-001 — One work graph

a subtask hangs wherever its root task hangs and is never placed alone; a task's own fields are read through any project that shows it, while a project's section, fields, files and history entries are read only by that project's readers; a project's first prefix numbers its existing tasks oldest first, and a changed prefix keeps every number and keeps the old references as aliases; a no-project task stays its owner's and is never quietly moved into a project (PEG-073 owns reviewed visibility changes). PEG-002 inherits the field library (text and number exist now), PEG-010 the file and comment rules, PEG-027 the versioned API.

## PEG-002 — Fields, statuses and shared definitions

a library definition and each task value retain one immutable field identity across adopting projects. Recurring projects adopt those same field identities and retain separate task values; a changed pinned definition holds generation for a newly reviewed template. Project status labels map to the shared To do/Doing/Done work state. Formulas use field keys and arithmetic; relationship rollups sum a named numeric source over selected tasks, with every dependency checked at read time. A definition change requires Admin authority on every adopting project and a current preview, and refuses any conversion that would alter or discard stored or calculated values. Tags are independent records; their project associations or personal custody govern catalogue visibility, and counts deduplicate only readable tasks. PEG-003/012/018/027 inherit these calculation, field-write and tag-authorization services.

## PEG-004 — Dependencies and believable schedules

Dependencies cross projects within one workspace and support all four types, positive lag, negative lead and zero-duration milestones. The same graph computes exact slack and critical-path membership. Working calendar settings persist the workspace timezone and weekday hours; personal full-day and timed leave affect only authorized scheduling, without collecting private reasons. Timed shifts preserve productive duration across working hours and DST. Timeline previews a held horizontal drag before release; List, Path, Calendar and Task detail use the same reviewed Apply door. The exact change set names owners, planned hours, timezone, dates and conflicts. Stale sets and impossible completed-dependent constraints leave every affected record unchanged. Immutable baselines retain their original dates. Existing deterministic workflow bundle rules record an exact Admin-reviewed dependency scope; coherent in-scope dates, assignments and work actions apply together once, while an outside cascade stays pending without hidden work in its run log or any partial effects. An authorized human can review and approve that exact held run without widening its standing activation. Native Inbox readiness follows the committed last-blocker transition, deduplicates concurrent completion and honors current assignee access and preferences. The agent’s named approver is chosen by the proposing agent’s request and must be a human who is not an analyst or guest.

## PEG-005 — Recurring work and human decisions

recurrence previews and pins an immutable template, then generates each local date once in one transaction across restarts, concurrent runners and DST. It copies no decisions, time, comments or files; PEG-089 applies only the explicitly reviewed internal standing audience. Agents never decide, and completing an ordinary task never signs an approval task. A decision sends nothing outward; internal approval notices are PEG-009/037. A recurring project's occurrence receives PEG-089's recorded internal audience after a reviewed preview. A task occurrence joins only its pinned home projects, with the activator's authority rechecked on each of them at every generation. Every existing sign-off reopening door writes an attributed history entry in the same transaction. Named approvers, stages, quorum, delegates and approve-only guests are PEG-036. Reviewed occurrence audiences, unreachable assignees and schedule oversight are PEG-089.

## PEG-006 — Useful reusable templates

New project offers all five gallery families, exact role and working-date previews, dependencies, fields and workload impact. Native task and project capture replaces source assignees with role placeholders and retains source authority. A missing role requires an explicit person or explicit unassigned choice. Immutable template versions never mutate an existing application without exact reviewed adoption; later human edits are preserved. Direct Duplicate project is a separate Settings door with fresh work identities and authorized source backlinks. New projects are private; copied membership paths retain their current scope, capped capabilities and expiry, and membership and rule activation is a separate exact review. Copied work receives no prior proof approval or outgoing decision notice. A currently authorized human Admin can activate a pinned deterministic new-task mapping; publishing a new template head or changing that mapping holds further execution. Selected pending triggers can be rebound only through a concrete reviewed mapping, retaining their previous definition and source lineage. Agent-selected templates and dates require exact human review; template-generated work cannot recursively trigger template rules. PEG-012, PEG-016, PEG-064, PEG-065 and PEG-087 inherit the corresponding broader rule, availability, recovery, custody and conversion obligations.

## PEG-087 — Convert work without losing its history

Conversion is available from native task and project records and the signed-in API. Exact reviewed mappings retain source work identities, original evidence contexts, scoped memberships, grant expiry and source classification. Project conversion retains selected nested work and explicit links for excluded roots; unrepresentable project settings are individually counted and linked as inert repair context. Personal work cannot be disclosed by conversion. Revision and authority fences protect the entire affected scope; retries return the same conversion. Undo restores only unchanged owned parent and placement effects, retains the linked container as a stable historical record and preserves later native edits. Existing approval decisions stay historical, and changed approval work requires a fresh human decision. PEG-064 and PEG-065 retain their broader recovery and custody obligations.

## PEG-034 — Reusable workflow bundles

workspace administrators publish immutable component versions and review exact projects and selected compatible components. Field components pin shared definition identity and version; a conflicting identity or changed definition refuses adoption. Saved views filter the existing List; task templates create fresh work; approval stages create the next fresh approval task only after all previous stages have current human approval under PEG-005’s existing independent administrator authority. The current deterministic rule sets a new task’s priority inside the reviewed project. Local rule overrides survive upgrades. Queued actions recheck activation, component configuration, generation and the activating human’s current authority; upgrade or disable cancels the old queue. Existing work, decisions and history remain intact. Restored bundles are inactive.

## PEG-035 — Risks, decisions and change requests

the register uses current project and linked-task access. Its named approver must be a human with current project settings authority; accepting a change rechecks its exact scope and the existing schedule preview, including every dependency shift, and commits the decision and changes together. Original values and rejected alternatives remain immutable. Citations use PEG-013’s existing status publication door and are filtered against current record access. Engineering references are links, with no duplicate issue creation.

## PEG-082 — Resumable attachments with owned byte custody

Completed attachment bytes and proof versions live in the installation’s own US R2 bucket, registered in Base’s createPortability({db, buckets, policy}) buckets and bucket/object-reference policy; a metadata row, external URL or unregistered parallel store cannot satisfy custody. This follows [Base’s portable bucket contract](https://raw.githubusercontent.com/runeditrun/base/main/modules/portability/README.md) and Coffer GIVE-002’s FILES-bucket precedent.

## PEG-013 — Portfolios that roll up truthfully

a portfolio's figures count the distinct tasks of the projects beneath it that the viewer can read; milestones are counted apart from tasks and a project the viewer cannot read leaves no trace. The risk policy belongs to a portfolio and its owner or admins; the policy of the portfolio being viewed evaluates every project beneath it and each change is a new version. A project with no published status is unknown rather than flagged by age, and the overdue share compares whole numbers against the policy percentage. Slack and the critical path are read from the dependency links among tasks the viewer can read, with weekends and observed US federal holidays skipped. The status door records a person's published statement for a project or portfolio they administer; drafting, review and client publication remain PEG-015's, and dependency shifts, baselines and approvals remain PEG-004's.

## PEG-014 — Goals and OKRs linked to execution

goals, key results, weighted/deduplicated links and subgoals, numeric observations, attributed check-ins and overrides work through Goals and the signed-in API. PEG-090 defines current company/team/personal visibility, accountable owners and editors. Native signed-in human observations remain available. Reviewed CSV and single-goal API integration sources now exist; source events preserve their keyed external identity, source, authorizer, observation time and receipt time. PEG-027 and PEG-062 inherit this scoped source boundary when adding transport or agent doors. Missing, stale, restricted, ended-source or cyclic input yields no progress value even with an override. Freshness windows are set per goal; the contract sets no default.

## PEG-017 — Task time and approved timesheets

timers persist their start instant and operation key, record elapsed whole seconds and share a per-person running-timer constraint. Manual entries preserve person, project/task, work date, timezone, notes and source; estimates deduplicate by task. Submission and review use exact revision tokens, returned manual edits retain before/after history, approved rows lock at the database boundary and later corrections are separate signed adjustments. CSV preserves entry IDs, references and exact seconds. Read-only Harvest/QuickBooks Time packets map approved entries to official request schemas and compare user-supplied complete readbacks without sending. PEG-042's reviewed send door delivers the same exact packet to Harvest or QuickBooks Time. It records one acknowledged provider entry per approved entry and receiver account, reconciles the provider's reported references and exact duration, and applies approved adjustments as corrections. Missing mappings and QuickBooks Time manual durations that would round stay pending with original identities and seconds. Gauge still needs its own compatible approved-time door. Delegated manager/project-Admin review, access lost after return and authority changes during review are PEG-088. PEG-018/042 inherit approved-only, current-access time reads and stable entry identities.

## PEG-020 — Server-enforced roles and administration

effective capability is the union of every current path (direct, team, project default, owner, workspace administrator), each capped by the kind of person: an analyst holds at most Viewer, an agent at most Editor and never Admin, a guest never reads internal-only work or workspace-wide shares; workspace owners and administrators hold Admin on every team and project of their workspace and on no personal task; approver and fallback deciders delegate up to Editor, Admin only with Admin authority; a decision commits only if the authority epoch, the target's policy revision and both people's standing are unchanged. Webhook registration is authorized here and delivered by PEG-027; reactions (PEG-010), rules (PEG-012) and templates (PEG-006) must call the same capability check.

## PEG-073 — Private personal work and a predictable day

personal settings and layout belong only to the person. The live local day evaluates saved group-to-section rules once per task/rule/day, retains an undo log and refuses undo over a later manual move. Calendar day previews are read-only. Sharing a personal root into a project reviews its task/subtask conversation/history and the current effective project audience, fences concurrent content/authority changes and leaves existing personal files in owner custody. Personal collaborators are added only after this reviewed project share. PEG-009 inherits the same ordering and PEG-027/062 inherit the same owner-only read and reviewed-share services.

## PEG-042 — Reconciled time handoff to specialist systems

native approved-time packets and a read-only comparison door support Harvest and QuickBooks Time official schemas; supplied readbacks are explicitly unverified. A reviewed send door delivers an approved sheet's exact packet to Harvest or QuickBooks Time. A durable ledger keeps one row per approved entry and receiver account. Each row is claimed before its request and records the provider acknowledgment (entry ID and reported duration), the provider's rejection status and reason, or an uncertain outcome. The next send reads an uncertain row back by Pegboard ID before writing, and an acknowledged entry is never resent. An acknowledgment reconciles only when the provider's record carries the reviewed person, project/task or job code, date and exact duration. Approved adjustments correct the acknowledged entry only while the provider still holds the exact prior total, one correction at a time. Rejected and uncertain rows are never retried without a person's send. Delivery calls only identity and time-entry endpoints. Choosing the authoritative system per field, and provider-initiated rejection or correction feeds, are not built. These doors inherit PEG-017 current-work access and approval locks; PEG-027/062 must retain the same boundary when adding transports or agent scopes.
